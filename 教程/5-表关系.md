# 5-表关系

本文基于 `gyyun-dao` 的初始化建表脚本、实体类 `@TableName` 注解和 MyBatis Mapper SQL 梳理数据库表关系。当前项目的主业务库以 DolphinScheduler 调度元数据为核心，业务表大多没有数据库外键约束，关系主要由 `code`、`version`、`id`、`project_code`、`user_id`、`workflow_instance_id` 等字段在代码层维护。

参考入口：

- 建表脚本：`gyyun-dao/src/main/resources/sql/gyyun_mysql.sql`
- 实体目录：`gyyun-dao/src/main/java/com/gyyun/ds/dao/entity`
- Mapper 目录：`gyyun-dao/src/main/resources/com/gyyun/ds/dao/mapper`

## 二、关系字段约定

项目同时使用数据库自增 `id` 和全局业务 `code`。理解这套库，关键是先分清哪些地方按 `id` 关联，哪些地方按 `code/version` 关联。

| 字段类型 | 典型字段 | 业务含义 |
| --- | --- | --- |
| 自增主键 | `id` | 单表物理主键，权限关系表、实例表通常按 `id` 关联 |
| 业务编码 | `code` | 项目、工作流、任务、环境、集群等业务唯一编码 |
| 版本字段 | `version` | 工作流定义、任务定义、DAG 关系的版本 |
| 项目编码 | `project_code` | 指向 `t_ds_project.code`，不是 `t_ds_project.id` |
| 用户主键 | `user_id`、`executor_id`、`operator` | 指向 `t_ds_user.id`，语义分别是创建人、执行人、操作人 |
| 工作流定义 | `workflow_definition_code`、`workflow_definition_version` | 指向工作流定义当前表或历史表的 `code/version` |
| 任务定义 | `task_code`、`task_definition_version`、`pre_task_code`、`post_task_code` | 指向任务定义当前表或历史表的 `code/version` |
| 工作流实例 | `workflow_instance_id` | 指向 `t_ds_workflow_instance.id` |
| 任务实例 | `task_instance_id`、`task_id` | 指向 `t_ds_task_instance.id` |
| Worker Group | `worker_group` | 指向 `t_ds_worker_group.name`，不是 `id` |
| 环境编码 | `environment_code` | 指向 `t_ds_environment.code` |
| 租户编码 | `tenant_code` | 指向 `t_ds_tenant.tenant_code` |

## 三、主表视角关系

### 1. `t_ds_project` 项目主表

项目是多数调度元数据的业务根节点。`t_ds_project.id` 是物理主键，`t_ds_project.code` 是跨表使用最频繁的项目业务键。

| 关联方向 | 关联字段 | 关系说明 |
| --- | --- | --- |
| `t_ds_project.user_id -> t_ds_user.id` | `user_id` | 项目创建人 |
| `t_ds_workflow_definition.project_code -> t_ds_project.code` | `project_code` | 一个项目下有多个工作流定义 |
| `t_ds_task_definition.project_code -> t_ds_project.code` | `project_code` | 一个项目下有多个任务定义 |
| `t_ds_workflow_instance.project_code -> t_ds_project.code` | `project_code` | 工作流实例冗余保存所属项目 |
| `t_ds_task_instance.project_code -> t_ds_project.code` | `project_code` | 任务实例冗余保存所属项目 |
| `t_ds_project_parameter.project_code -> t_ds_project.code` | `project_code` | 项目级参数 |
| `t_ds_project_preference.project_code -> t_ds_project.code` | `project_code` | 项目偏好配置，一项目一条 |
| `t_ds_relation_project_user.project_id -> t_ds_project.id` | `project_id` | 用户项目授权，注意这里用项目 `id` |
| `t_ds_relation_project_worker_group.project_code -> t_ds_project.code` | `project_code` | 项目可用 Worker Group |
| `t_ds_task_group.project_code -> t_ds_project.code` | `project_code` | 项目内任务组 |
| `t_ds_workflow_task_relation.project_code -> t_ds_project.code` | `project_code` | DAG 边关系所属项目 |
| `t_ds_workflow_task_lineage.dept_project_code -> t_ds_project.code` | `dept_project_code` | 依赖任务所属项目 |

同表强业务字段：

| 字段 | 关系强度 | 说明 |
| --- | --- | --- |
| `code` | 强 | 全局唯一业务编码，绝大多数项目级子表使用它关联项目 |
| `name` | 强 | 唯一项目名 |
| `user_id` | 强 | 创建人，项目权限和项目列表查询都会展示用户信息 |
| `flag` | 中 | 项目是否可用，属于逻辑状态字段 |

### 2. `t_ds_workflow_definition` 工作流定义主表

工作流定义是 DAG、定时调度、命令和实例的业务核心。当前表保存当前版本，历史版本进入 `t_ds_workflow_definition_log`。

| 关联方向 | 关联字段 | 关系说明 |
| --- | --- | --- |
| `t_ds_workflow_definition.project_code -> t_ds_project.code` | `project_code` | 工作流归属项目 |
| `t_ds_workflow_definition.user_id -> t_ds_user.id` | `user_id` | 工作流创建人 |
| `t_ds_workflow_definition.warning_group_id -> t_ds_alertgroup.id` | `warning_group_id` | 工作流默认告警组，DDL 和 Mapper 中存在该字段 |
| `t_ds_workflow_definition_log.code/version -> t_ds_workflow_definition.code/version` | `code`, `version` | 历史版本快照 |
| `t_ds_workflow_task_relation.workflow_definition_code/version -> t_ds_workflow_definition.code/version` | `workflow_definition_code`, `workflow_definition_version` | 工作流 DAG 边 |
| `t_ds_schedules.workflow_definition_code -> t_ds_workflow_definition.code` | `workflow_definition_code` | 工作流定时配置，一工作流最多一条当前调度配置 |
| `t_ds_command.workflow_definition_code/version -> t_ds_workflow_definition.code/version` | `workflow_definition_code`, `workflow_definition_version` | 待执行命令 |
| `t_ds_error_command.workflow_definition_code/version -> t_ds_workflow_definition.code/version` | `workflow_definition_code`, `workflow_definition_version` | 失败命令 |
| `t_ds_workflow_instance.workflow_definition_code/version -> t_ds_workflow_definition.code/version` | `workflow_definition_code`, `workflow_definition_version` | 工作流运行实例 |
| `t_ds_alert.workflow_definition_code -> t_ds_workflow_definition.code` | `workflow_definition_code` | 工作流相关告警 |
| `t_ds_workflow_task_lineage.workflow_definition_code/version -> t_ds_workflow_definition.code/version` | `workflow_definition_code`, `workflow_definition_version` | 依赖血缘所属工作流 |

同表强业务字段：

| 字段 | 关系强度 | 说明 |
| --- | --- | --- |
| `code` | 强 | 工作流全局业务编码，当前表唯一 |
| `version` | 强 | 当前版本号，和历史表、DAG 关系一起组成版本化视图 |
| `name + project_code` | 强 | 同一项目下工作流名称唯一 |
| `project_code` | 强 | 所属项目，控制权限、列表和移动/复制范围 |
| `release_state` | 强 | 上线/下线状态，影响是否可调度和运行 |
| `global_params` | 强 | 工作流全局参数，实例启动时会下发到运行上下文 |
| `locations` | 中 | 前端 DAG 节点布局信息 |
| `warning_group_id` | 中 | 告警组业务引用 |
| `timeout`、`execution_type` | 中 | 工作流运行控制策略 |

### 3. `t_ds_task_definition` 任务定义主表

任务定义描述一个 DAG 节点的静态配置。任务定义同样有当前表和历史表，运行时任务实例会记录任务定义的 `code/version` 快照。

| 关联方向 | 关联字段 | 关系说明 |
| --- | --- | --- |
| `t_ds_task_definition.project_code -> t_ds_project.code` | `project_code` | 任务归属项目 |
| `t_ds_task_definition.user_id -> t_ds_user.id` | `user_id` | 任务创建人 |
| `t_ds_task_definition.environment_code -> t_ds_environment.code` | `environment_code` | 任务默认环境 |
| `t_ds_task_definition.worker_group -> t_ds_worker_group.name` | `worker_group` | 任务默认 Worker Group |
| `t_ds_task_definition.task_group_id -> t_ds_task_group.id` | `task_group_id` | 任务组并发控制 |
| `t_ds_task_definition_log.code/version -> t_ds_task_definition.code/version` | `code`, `version` | 任务历史版本 |
| `t_ds_workflow_task_relation.pre_task_code/version -> t_ds_task_definition.code/version` | `pre_task_code`, `pre_task_version` | 上游任务节点 |
| `t_ds_workflow_task_relation.post_task_code/version -> t_ds_task_definition.code/version` | `post_task_code`, `post_task_version` | 下游任务节点 |
| `t_ds_task_instance.task_code/task_definition_version -> t_ds_task_definition_log.code/version` | `task_code`, `task_definition_version` | 任务实例对应的定义版本 |
| `t_ds_workflow_task_lineage.task_definition_code/version -> t_ds_task_definition.code/version` | `task_definition_code`, `task_definition_version` | 本任务的跨工作流依赖血缘 |

同表强业务字段：

| 字段 | 关系强度 | 说明 |
| --- | --- | --- |
| `code + version` | 强 | 任务定义版本化身份，DAG 边和实例都依赖它 |
| `project_code` | 强 | 任务所属项目 |
| `task_type + task_params` | 强 | 任务插件类型和插件参数 JSON，是任务真正的执行配置 |
| `worker_group + environment_code` | 强 | 任务执行资源选择 |
| `fail_retry_times + fail_retry_interval` | 中 | 失败重试策略 |
| `timeout_flag + timeout_notify_strategy + timeout` | 中 | 超时策略 |
| `resource_ids` | 中 | 资源 ID 列表，脚本中是逗号分隔字符串 |
| `task_group_id + task_group_priority` | 中 | 任务组排队和优先级 |
| `cpu_quota + memory_max` | 中 | 资源限额 |

### 4. `t_ds_workflow_task_relation` 工作流 DAG 关系表

这张表是工作流定义和任务定义之间最重要的关系表。它不是简单的中间表，而是 DAG 的边表，描述一个工作流版本中任务之间的依赖方向。

| 关联方向 | 关联字段 | 关系说明 |
| --- | --- | --- |
| `workflow_definition_code/version -> t_ds_workflow_definition.code/version` | `workflow_definition_code`, `workflow_definition_version` | 这条边属于哪个工作流版本 |
| `pre_task_code/version -> t_ds_task_definition.code/version` | `pre_task_code`, `pre_task_version` | 上游任务 |
| `post_task_code/version -> t_ds_task_definition.code/version` | `post_task_code`, `post_task_version` | 下游任务 |
| `t_ds_workflow_task_relation_log` | 同名字段 | DAG 边历史版本 |

同表强业务字段：

| 字段 | 关系强度 | 说明 |
| --- | --- | --- |
| `workflow_definition_code + workflow_definition_version` | 强 | 约束边属于哪个工作流版本 |
| `pre_task_code + pre_task_version` | 强 | 上游节点。根节点常见 `pre_task_code = 0` 的占位语义 |
| `post_task_code + post_task_version` | 强 | 下游节点 |
| `condition_type + condition_params` | 强 | 条件分支、延迟等边条件 |
| `project_code` | 强 | 项目范围，很多查询用它过滤 DAG 边 |

### 5. `t_ds_workflow_instance` 工作流实例主表

工作流实例是一次工作流运行的主记录。它既保存定义快照字段，也保存运行态、命令参数和调度资源。

| 关联方向 | 关联字段 | 关系说明 |
| --- | --- | --- |
| `workflow_definition_code/version -> t_ds_workflow_definition.code/version` | `workflow_definition_code`, `workflow_definition_version` | 实例来自哪个工作流定义版本 |
| `project_code -> t_ds_project.code` | `project_code` | 实例所属项目 |
| `executor_id -> t_ds_user.id` | `executor_id` | 触发/执行用户 |
| `warning_group_id -> t_ds_alertgroup.id` | `warning_group_id` | 实例告警组 |
| `worker_group -> t_ds_worker_group.name` | `worker_group` | 实例级 Worker Group |
| `environment_code -> t_ds_environment.code` | `environment_code` | 实例级环境 |
| `tenant_code -> t_ds_tenant.tenant_code` | `tenant_code` | 实例运行租户 |
| `t_ds_task_instance.workflow_instance_id -> t_ds_workflow_instance.id` | `workflow_instance_id` | 一个工作流实例包含多个任务实例 |
| `t_ds_relation_workflow_instance.parent_workflow_instance_id/workflow_instance_id -> t_ds_workflow_instance.id` | `parent_workflow_instance_id`, `workflow_instance_id` | 父子工作流实例 |
| `t_ds_relation_sub_workflow.parent_workflow_instance_id/sub_workflow_instance_id -> t_ds_workflow_instance.id` | `parent_workflow_instance_id`, `sub_workflow_instance_id` | 子工作流实例 |
| `t_ds_alert.workflow_instance_id -> t_ds_workflow_instance.id` | `workflow_instance_id` | 实例告警 |
| `t_ds_serial_command.workflow_instance_id -> t_ds_workflow_instance.id` | `workflow_instance_id` | 串行命令关联实例 |
| `t_ds_task_group_queue.workflow_instance_id -> t_ds_workflow_instance.id` | `workflow_instance_id` | 任务组排队记录所属实例 |

同表强业务字段：

| 字段 | 关系强度 | 说明 |
| --- | --- | --- |
| `workflow_definition_code + workflow_definition_version` | 强 | 定义版本快照 |
| `state + state_history` | 强 | 实例状态机和状态历史 |
| `command_type + command_param + history_cmd` | 强 | 运行命令来源和操作历史 |
| `schedule_time + command_start_time + start_time + end_time` | 强 | 调度、命令和实际执行时间链路 |
| `executor_id + executor_name` | 中 | 执行用户快照 |
| `worker_group + tenant_code + environment_code` | 强 | 运行资源上下文 |
| `is_sub_workflow` | 中 | 是否子工作流实例 |
| `next_workflow_instance_id` | 强 | 串行工作流自关联队列，指向下一条工作流实例 |
| `global_params + var_pool` | 强 | 运行时参数池 |

### 6. `t_ds_task_instance` 任务实例主表

任务实例是一次具体任务执行。它连接工作流实例、任务定义版本、任务组排队和任务上下文。

| 关联方向 | 关联字段 | 关系说明 |
| --- | --- | --- |
| `workflow_instance_id -> t_ds_workflow_instance.id` | `workflow_instance_id` | 所属工作流实例 |
| `task_code/task_definition_version -> t_ds_task_definition_log.code/version` | `task_code`, `task_definition_version` | 任务定义版本快照 |
| `project_code -> t_ds_project.code` | `project_code` | 所属项目 |
| `executor_id -> t_ds_user.id` | `executor_id` | 执行人 |
| `worker_group -> t_ds_worker_group.name` | `worker_group` | 实际执行 Worker Group |
| `environment_code -> t_ds_environment.code` | `environment_code` | 实际执行环境 |
| `task_group_id -> t_ds_task_group.id` | `task_group_id` | 任务组 |
| `t_ds_task_instance_context.task_instance_id -> t_ds_task_instance.id` | `task_instance_id` | 任务实例上下文 |
| `t_ds_task_group_queue.task_id -> t_ds_task_instance.id` | `task_id` | 任务组排队记录 |
| `t_ds_relation_workflow_instance.parent_task_instance_id -> t_ds_task_instance.id` | `parent_task_instance_id` | 触发子工作流的父任务实例 |

同表强业务字段：

| 字段 | 关系强度 | 说明 |
| --- | --- | --- |
| `workflow_instance_id + task_code` | 强 | 一个工作流实例内定位某个任务运行 |
| `task_code + task_definition_version` | 强 | 任务定义版本快照 |
| `state` | 强 | 任务实例状态机 |
| `submit_time + first_submit_time + start_time + end_time` | 强 | 任务生命周期时间 |

### 7. `t_ds_command`、`t_ds_error_command` 和 `t_ds_serial_command`

命令表是 Master 调度循环的入口。API 或定时器生成命令，Master 消费 `t_ds_command` 后创建或驱动工作流实例；异常命令落入 `t_ds_error_command`；串行执行模式还会使用 `t_ds_serial_command`。

| 表 | 关键关联 | 说明 |
| --- | --- | --- |

| `t_ds_command` | `executor_id -> t_ds_user.id` | 命令执行人 |
| `t_ds_command` | `warning_group_id -> t_ds_alertgroup.id` | 告警组 |
| `t_ds_command` | `worker_group/environment_code/tenant_code` | 运行资源上下文 |
| `t_ds_error_command` | 与 `t_ds_command` 基本一致 | 失败命令额外保存 `message` |
| `t_ds_serial_command` | `workflow_instance_id -> t_ds_workflow_instance.id` | 串行工作流实例队列 |

同表强业务字段：

| 字段 | 关系强度 | 说明 |
| --- | --- | --- |
| `command_type + command_param` | 强 | 命令类型和 JSON 参数 |
| `workflow_definition_code + workflow_definition_version` | 强 | 命令目标工作流版本 |
| `workflow_instance_id` | 中 | 重跑、恢复、补数等场景关联实例 |
| `task_depend_type + failure_strategy` | 中 | 运行策略 |
| `workflow_instance_priority` | 中 | Master 拉取命令时参与排序 |
| `worker_group + tenant_code + environment_code` | 强 | 命令携带的运行资源上下文 |
| `dry_run` | 中 | 是否试运行 |

## 六、需要特别注意的历史或弱关系

1. 业务表多数没有数据库外键。除了 Quartz 表，`t_ds_*` 表的关系主要靠 Mapper SQL、唯一索引和服务层逻辑维护。
2. `code` 和 `id` 混用是常态。项目授权表用 `project_id -> t_ds_project.id`，但大多数项目子表使用 `project_code -> t_ds_project.code`。
3. Worker Group 跨表保存 `name`，不是保存 `t_ds_worker_group.id`。重命名 Worker Group 会影响多处业务字段。
4. 环境跨表保存 `environment_code`，默认值常见为 `-1`，表示不指定环境。
5. 任务插件参数中的强关系字段在 `task_params` JSON 内，例如 SQL 任务的数据源、子工作流任务的工作流编码、资源引用等，DDL 层看不到这些关系。
6. `t_ds_resources`、`t_ds_relation_resources_user` 在初始化脚本中标注 Deprecated，但仍属于当前建表脚本的一部分。
7. Mapper 中仍可看到历史残留引用：`t_ds_trigger_relation` 在旧升级脚本中创建、后续升级脚本中删除；`UserMapper.xml` 引用了 `t_ds_relation_user_alertgroup`，但当前初始化 DDL 没有创建该表。分析当前库结构时不应把它们当作当前主表。
8. `t_ds_workflow_definition_log`、`t_ds_task_definition_log`、`t_ds_workflow_task_relation_log` 是版本快照表。实例和 DAG 查询经常按 `code/version` 回查历史版本，不能只看当前表。
