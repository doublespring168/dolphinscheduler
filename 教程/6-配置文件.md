# 6-配置文件

本文梳理当前项目各模块的主要配置文件、配置项及作用。项目是 Apache DolphinScheduler，多数运行配置由 Spring Boot `application.yaml`、公共 `common.properties`、资源中心配置和部署配置共同组成。

## 一、配置文件总览

| 模块/目录 | 配置文件 | 主要作用 |
| --- | --- | --- |
| `gyyun-api` | `src/main/resources/application.yaml` | API 服务端口、上下文路径、数据库、认证、限流、Python Gateway、Actuator、注册中心等 |
| `gyyun-api` | `task-type-config.yaml` | Web UI 默认展示的任务类型分类 |
| `gyyun-api` | `dynamic-task-type-config.yaml` | 动态任务类型的名称、图标、悬浮提示、JSON 配置 |
| `gyyun-api` | `swagger.properties` | OpenAPI/Swagger 文档开关与路径 |
| `gyyun-api` | `i18n/messages*.properties` | API 返回信息的国际化文案 |
| `gyyun-api` | `logback-spring.xml` | API 服务日志输出、滚动策略 |
| `gyyun-master` | `src/main/resources/application.yaml` | Master 调度服务配置、负载保护、命令拉取、Worker 负载均衡、注册中心 |
| `gyyun-master` | `logback-spring.xml` | Master 服务日志与任务日志 |
| `gyyun-worker` | `src/main/resources/application.yaml` | Worker 执行服务配置、线程池、租户、负载保护、注册中心 |
| `gyyun-worker` | `logback-spring.xml` | Worker 服务日志与任务日志 |
| `gyyun-alert/gyyun-alert-server` | `application.yaml` | Alert Server 端口、并发、数据库、注册中心、Actuator |
| `gyyun-alert/gyyun-alert-server` | `logback-spring.xml` | Alert 服务日志 |
| `gyyun-standalone-server` | `application.yaml` | 单机模式把 API/Master/Worker/Alert 放在同一个进程内运行 |
| `gyyun-standalone-server` | `logback-spring.xml` | Standalone 服务日志与任务日志 |
| `gyyun-tools` | `application.yaml` | 数据库初始化、升级等工具命令的数据库和 MyBatis 配置 |
| `gyyun-common` | `common.properties` | 资源存储、HDFS/YARN/Kerberos、Shell、MLflow、远程日志开关等公共运行配置 |
| `gyyun-common` | `resource-center.yaml` | 对象存储和云资源中心相关账号、桶、区域、端点 |
| `gyyun-common` | `remote-logging.yaml` | 任务日志上传远程存储的目标、目录、线程池、云存储账号 |
| `gyyun-authentication/gyyun-aws-authentication` | `aws.yaml` | AWS S3/EMR/SageMaker/DMS/DataSync 的认证、区域、端点 |
| `gyyun-yarn-aop` | `log4j.properties` | YARN AOP 插件日志输出格式 |
| `gyyun-meter` | `grafana-demo/*.yaml` | Prometheus 抓取 DolphinScheduler 指标，Grafana 自动加载数据源和仪表盘 |
| `gyyun-ui` | `.env.development`、`.env.production` | 前端开发/生产环境变量 |
| `gyyun-ui` | `vite.config.ts` | Vite 构建、压缩、别名、开发代理 |
| `gyyun-ui` | `tsconfig.json` | TypeScript 编译规则 |
| `gyyun-ui` | `.eslintrc.js`、`.prettierrc.js` | 前端代码检查和格式化规则 |
| `deploy/docker` | `.env`、`docker-compose.yml` | Docker Compose 镜像、服务、端口、卷、健康检查、外部化运行参数 |
| `deploy/kubernetes/gyyun` | `values.yaml` | Helm Chart 的镜像、依赖服务、公共配置、组件副本、探针、持久化、Ingress |

## 二、Spring Boot 服务通用配置

API、Master、Alert、Standalone、Tools 等服务都使用 Spring Boot 配置体系。以下配置项在多个模块中重复出现。

| 配置项 | 作用 |
| --- | --- |
| `spring.application.name` | 当前 Spring 应用名称，用于日志、指标标签和服务识别 |
| `spring.profiles.active` | 激活数据库或运行环境 profile，例如 `postgresql`、`mysql`、`h2` |
| `spring.banner.charset` | Banner 字符集 |
| `spring.jackson.time-zone` | JSON 序列化/反序列化时区 |
| `spring.jackson.date-format` | JSON 日期时间格式 |
| `spring.datasource.driver-class-name` | JDBC 驱动类 |
| `spring.datasource.url` | 数据库连接 URL |
| `spring.datasource.username` | 数据库用户名 |
| `spring.datasource.password` | 数据库密码 |
| `spring.datasource.hikari.*` | HikariCP 连接池参数，控制连接数、超时、连接生命周期等 |
| `spring.quartz.job-store-type` | Quartz JobStore 类型，一般为 JDBC |
| `spring.quartz.jdbc.initialize-schema` | 是否初始化 Quartz 表结构 |
| `spring.quartz.properties.*` | Quartz 调度器实例、线程池、持久化、数据库代理类等参数 |
| `scheduler-plugin.quartz.using-separate-datasource` | Quartz 是否使用独立数据源 |
| `scheduler-plugin.quartz.hikari.*` | Quartz 独立数据源开启时的连接池配置 |
| `mybatis-plus.global-config.db-config.id-type` | MyBatis-Plus 主键生成策略 |
| `mybatis-plus.global-config.db-config.logic-delete-field` | 逻辑删除字段 |
| `mybatis-plus.global-config.db-config.logic-delete-value` | 逻辑删除值 |
| `mybatis-plus.global-config.db-config.logic-not-delete-value` | 逻辑未删除值 |
| `mybatis-plus.mapper-locations` | Mapper XML 扫描路径 |
| `mybatis-plus.type-aliases-package` | 实体别名扫描包 |
| `management.security.enabled` | Actuator 管理端点是否开启鉴权 |
| `management.security.username` | Actuator 鉴权用户名 |
| `management.security.password` | Actuator 鉴权密码 |
| `management.security.exclude` | 开启鉴权后仍可匿名访问的端点，如 `health,metrics` |
| `management.endpoints.web.exposure.include` | 暴露的 Actuator 端点，项目默认包含 `health`、`metrics`、`prometheus` |
| `management.endpoint.health.show-details` | 健康检查详情展示策略 |
| `management.endpoint.health.enabled` | 是否启用健康检查端点 |
| `management.health.db.enabled` | 健康检查是否包含数据库状态 |
| `management.metrics.tags.application` | Micrometer 指标里的应用标签 |
| `registry.type` | 注册中心类型，支持 ZooKeeper、Etcd、JDBC 等插件 |
| `registry.zookeeper.namespace` | ZooKeeper 注册根命名空间 |
| `registry.zookeeper.connect-string` | ZooKeeper 地址 |
| `registry.zookeeper.retry-policy.*` | ZooKeeper 重试策略 |
| `registry.zookeeper.digest` | ZooKeeper Digest 认证信息 |
| `registry.zookeeper.session-timeout` | ZooKeeper 会话超时时间 |
| `registry.zookeeper.connection-timeout` | ZooKeeper 连接超时时间 |
| `registry.zookeeper.block-until-connected` | 启动时是否阻塞等待连接成功 |
| `server.port` | 当前服务 HTTP 端口 |

注册中心为 Etcd 或 JDBC 时，服务也会读取 `registry.*` 下的插件配置：

| 配置项 | 作用 |
| --- | --- |
| `registry.endpoints` | Etcd 端点列表 |
| `registry.namespace` | Etcd/JDBC 注册命名空间 |
| `registry.connection-timeout` | Etcd 连接超时 |
| `registry.ttl` | Etcd 租约 TTL |
| `registry.user`、`registry.password` | Etcd 用户名和密码 |
| `registry.authority` | Etcd authority |
| `registry.retry-delay`、`registry.retry-max-delay`、`registry.retry-max-duration` | Etcd 重试等待策略 |
| `registry.load-balancer-policy` | Etcd gRPC 负载均衡策略 |
| `registry.cert-file`、`registry.key-cert-chain-file`、`registry.key-file` | Etcd TLS 证书配置 |
| `registry.jdbc-registry-client-name` | JDBC 注册客户端名称，默认会结合主机和端口生成 |
| `registry.heartbeat-refresh-interval` | JDBC 注册心跳刷新间隔 |
| `registry.session-timeout` | JDBC 注册会话过期时间 |
| `registry.hikari-config.*` | JDBC 注册中心使用的 Hikari 数据源配置 |

## 五、Worker 模块配置

### `gyyun-worker/src/main/resources/application.yaml`

| 配置项 | 作用 |
| --- | --- |
| `spring.autoconfigure.exclude` | Worker 默认排除 `DataSourceAutoConfiguration`，说明 Worker 本身不直接依赖业务数据库数据源 |
| `worker.listen-port` | Worker RPC 监听端口，默认 `1234` |
| `worker.max-heartbeat-interval` | Worker 心跳最大间隔 |
| `worker.host-weight` | Worker 主机权重，参与任务分发 |
| `worker.group` | Worker 所属分组，默认 `default` |
| `worker.server-load-protection.enabled` | Worker 负载保护开关 |
| `worker.server-load-protection.max-system-cpu-usage-percentage-thresholds` | 系统 CPU 使用率阈值 |
| `worker.server-load-protection.max-jvm-cpu-usage-percentage-thresholds` | JVM CPU 使用率阈值 |
| `worker.server-load-protection.max-system-memory-usage-percentage-thresholds` | 系统内存使用率阈值 |
| `worker.server-load-protection.max-disk-usage-percentage-thresholds` | 磁盘使用率阈值 |
| `worker.physical-task-config.task-executor-thread-size` | 物理任务执行线程池大小，默认 `100` |
| `worker.tenant-config.auto-create-tenant-enabled` | 执行任务时租户用户不存在是否自动创建 |
| `worker.tenant-config.default-tenant-enabled` | 租户为 `default` 时是否使用 Worker 启动用户执行任务 |
| `server.port` | Worker Actuator HTTP 端口，默认 `1235` |

Worker 也读取 `registry.*`、`management.*` 和公共任务配置。任务运行目录、Shell 环境、资源存储等不在 Worker 自己的 `application.yaml` 中，而是由 `gyyun-common` 的公共配置提供。

## 十八、关键配置关联关系

| 关联配置 | 关联关系 |
| --- | --- |
| `server.servlet.context-path=/gyyun/` 与 UI `base=/gyyun/ui/` | 后端 API 和前端静态资源共享同一个 DolphinScheduler 部署上下文 |
| `registry.*` 与 Master/Worker/Alert | 三类服务通过注册中心发现彼此，并上报心跳 |
| `master.worker-load-balancer-configuration-properties.*` 与 `worker.host-weight` | Master 根据 Worker 心跳、权重和负载指标选择任务执行节点 |
| `worker.group` 与任务 Worker Group | 任务分发时只会进入匹配的 Worker 分组 |
| `resource.storage.type` 与 `resource.*`/`aws.s3.*` | 资源存储类型决定实际读取哪组云存储或 HDFS 配置 |
| `remote.logging.enable` 与 `remote.logging.*` | 开启远程日志后，任务日志由本地日志路径同步到指定远程存储 |
| `common.properties` 的 `hadoop.security.authentication.startup.state` 与 Kerberos 配置 | 启用 Kerberos 后必须配套 `krb5.conf`、keytab 用户和 keytab 路径 |
| `datasource.encryption.enable` 与 `datasource.encryption.salt` | 数据源敏感字段加密开关和盐值必须配套使用 |
| `api.traffic-control.*` 与 API 拦截器 | API 请求会按全局和租户维度进行 QPS 控制 |
| `security.authentication.type` 与 LDAP/Casdoor/OAuth2/OIDC 子配置 | 认证类型决定实际使用哪组登录配置 |
| Helm `conf.common.*` 与 `common.properties` | Helm 会把 values 中的公共配置渲染到运行时配置 |
| Docker `.env` 与 Spring Boot 环境变量绑定 | `SPRING_DATASOURCE_URL`、`REGISTRY_ZOOKEEPER_CONNECT_STRING` 等环境变量会覆盖 YAML 中的同名配置 |
