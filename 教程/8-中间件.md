# DolphinScheduler 中间件

本文档根据当前项目的 `pom.xml`、各服务 `application.yaml`、`common.properties`、Docker Compose、Helm Chart，以及 API、Master、Worker、Alert、Registry、Scheduler、Storage、Datasource、Task、Alert Plugin 等源码整理，说明项目用到了哪些中间件，以及分别使用了这些中间件的哪些能力。

这里的“中间件”按广义理解：既包括服务运行必须依赖的数据库、注册中心、调度器、RPC、监控、安全组件，也包括通过插件接入的存储系统、数据源、大数据平台、容器平台、云服务和告警通道。

## 1. 结论总览

### 1.1 核心运行时中间件

| 中间件/组件 | 是否核心依赖 | 主要使用模块 | 项目使用的能力 |
| --- | --- | --- | --- |
| PostgreSQL / MySQL / H2 | 是 | `dolphinscheduler-dao`、`dolphinscheduler-api`、`dolphinscheduler-master`、`dolphinscheduler-alert`、`dolphinscheduler-tools` | 元数据持久化、工作流/任务运行数据、Quartz 调度表、告警事件、插件定义、会话和访问令牌 |
| HikariCP | 是 | DAO、数据源插件、Quartz 单独数据源配置 | JDBC 连接池、连接复用、连接检测、数据源插件连接池 |
| MyBatis Plus | 是 | `dolphinscheduler-dao` | ORM、Mapper、分页插件、数据库方言适配、实体与表映射 |
| Quartz | 是 | `dolphinscheduler-scheduler-plugin/dolphinscheduler-scheduler-quartz`、API、Master | Cron 定时调度、JDBC JobStore、集群调度、JobDetail/Trigger 管理、到点触发工作流 |
| ZooKeeper | 默认核心依赖 | `dolphinscheduler-registry-zookeeper`、API、Master、Worker、Alert | 注册中心、临时节点、服务发现、节点监听、分布式锁、Master/Alert HA |

| Spring Boot Actuator / Micrometer / Prometheus | 是 | `dolphinscheduler-meter`、各服务 | 健康检查、业务指标、RPC 指标、Prometheus 指标暴露 |

## 3. 定时调度中间件 Quartz

项目通过 `dolphinscheduler-scheduler-plugin` 抽象调度器，目前实际实现是 Quartz。

| 使用点 | 使用能力 |
| --- | --- |
| `SchedulerApi` | 对外只暴露 `start`、`insertOrUpdateScheduleTask`、`deleteScheduleTask`、`close`，避免调用方直接依赖 Quartz 类型 |
| `QuartzScheduler` | 创建/更新 `CronTrigger` 和 `JobDetail`，调用 `scheduler.scheduleJob` 注册定时任务 |
| `ProcessScheduleTask` | Quartz 到点执行后，通过 `IWorkflowControlClient.scheduleTriggerWorkflow` 触发工作流 |
| API Server | 配置 Quartz 但 `auto-startup: false`，主要用于管理 Schedule；使用 `QuartzZeroSizeThreadPool` 避免 API 执行调度任务 |
| Master Server | 真正启动 Quartz Scheduler，线程池默认 25；只有 Master Leader 负责运行调度器 |
| JDBC JobStore | `job-store-type: jdbc`，`QRTZ_` 表持久化 Job/Trigger，支持 Quartz 集群 |

Quartz 配置能力：

| 配置 | 说明 |
| --- | --- |
| `org.quartz.jobStore.isClustered: true` | 支持多实例集群调度 |
| `org.quartz.jobStore.class: LocalDataSourceJobStore` | 使用 Spring 本地数据源连接数据库 |
| `org.quartz.jobStore.tablePrefix: QRTZ_` | Quartz 表名前缀 |
| `org.quartz.jobStore.driverDelegateClass` | PostgreSQL 使用 `PostgreSQLDelegate`，MySQL profile 使用 `StdJDBCDelegate` |
| `org.quartz.scheduler.instanceId: AUTO` | 自动生成 Scheduler 实例 ID |
| `scheduler-plugin.quartz.using-separate-datasource` | 可选为 Quartz 配置独立 Hikari 数据源 |

调度链路：

```text
API 启用/更新定时 -> SchedulerService -> SchedulerApi -> Quartz Job/Trigger
Master Leader 启动 Quartz -> ProcessScheduleTask 到点执行
ProcessScheduleTask -> IWorkflowControlClient.scheduleTriggerWorkflow -> Master 创建调度命令/工作流实例
```

## 4. 注册中心和高可用中间件

项目把注册中心抽象为 `Registry` 接口，并通过 SPI 提供 ZooKeeper、Etcd、JDBC 三种实现。

### 4.1 Registry 抽象能力

| 接口能力 | 项目用途 |
| --- | --- |
| `start`、`isConnected`、`connectUntilTimeout` | 启动注册中心客户端，等待连接成功 |
| `put(key, value, deleteOnDisconnect)` | 写入持久节点或断开后删除的临时节点 |
| `get`、`children`、`exists`、`delete` | 查询服务节点、心跳内容和注册目录 |
| `subscribe(path, listener)` | 监听 Master、Worker、Alert 等节点变化 |
| `acquireLock`、`releaseLock` | 分布式锁、故障转移锁、HA 选主 |
| `addConnectionStateListener` | 注册中心连接状态变化监听 |

### 4.2 ZooKeeper

ZooKeeper 是默认注册中心。API、Master、Worker、Alert 默认配置：

```yaml
registry:
  type: zookeeper
  zookeeper:
    namespace: dolphinscheduler
    connect-string: localhost:2181
```

| 使用能力 | 说明 |
| --- | --- |
| Curator Client | 管理 ZooKeeper 连接、重试、会话超时、连接超时 |
| 临时节点 | Master、Worker、Alert 心跳节点断线自动删除 |
| 持久节点 | 初始化 `/master`、`/workers`、`/alert-server`、`/failover` 等目录 |
| TreeCache/监听 | 监听服务节点增删改，刷新集群状态 |
| InterProcessMutex | 分布式锁，用于 failover 和 HA 选主 |
| Digest | 支持可选的 ZooKeeper digest 认证 |

### 4.3 Etcd

Etcd 是可选注册中心，Helm 中通过 `registryEtcd.enabled` 启用。

| 使用能力 | 说明 |
| --- | --- |
| jetcd KV | 注册服务节点、读取心跳数据 |
| Watch | 监听节点变更 |
| Lease | 实现带 TTL 的临时数据和心跳续约 |
| Lock | 分布式锁 |
| TLS | 支持 `certFile`、`keyCertChainFile`、`keyFile` 等证书配置 |

### 4.4 JDBC Registry

JDBC Registry 是可选注册中心，适合不想引入 ZooKeeper/Etcd 的部署场景。

| 使用能力 | 说明 |
| --- | --- |
| 注册数据表 | 用数据库表保存 registry key/value |
| 心跳/过期 | 通过 term refresh 和 expire times 维护临时数据 |
| 锁表/锁记录 | 用数据库实现分布式锁 |
| 变更事件 | 用表记录 data change event，供订阅方感知变化 |
| 独立数据源 | 可默认复用 DolphinScheduler 元数据库，也可单独配置 Hikari 数据源 |

### 4.5 注册中心在业务中的用途

| 使用场景 | 说明 |
| --- | --- |
| 服务注册 | Master、Worker、Alert 启动后写入心跳节点 |
| 服务发现 | API 查询 Master/Worker/Alert 列表，Master 获取 WorkerGroup 中可用 Worker |
| 心跳状态 | 心跳 JSON 包含 host、port、进程、启动时间、上报时间、负载等信息 |
| 集群变化监听 | Master 订阅 Worker/Master 节点变化，更新调度目标和集群状态 |
| Master HA | Master 通过 HA Server 和注册中心锁选主，只有 Leader 启动调度器 |
| Alert HA | Alert Server 通过注册中心实现高可用 |
| 故障转移 | FailoverCoordinator 使用注册中心锁控制工作流/任务故障转移 |

## 5. RPC 中间件 Netty

项目内部进程间通信不使用 HTTP，也不依赖外部 MQ，而是通过 `dolphinscheduler-extract` 基于 Netty 实现 RPC。

### 5.1 RPC 使用范围

| RPC 契约 | 所在模块 | 主要能力 |
| --- | --- | --- |
| `IWorkflowControlClient` | `dolphinscheduler-extract-master` | API/Quartz/子工作流远程触发、暂停、停止、恢复、补数、重跑工作流 |
| `IWorkflowExecutorQueryClient` | `dolphinscheduler-extract-master` | 查询工作流执行状态 |
| `IPhysicalTaskExecutorOperator` | `dolphinscheduler-extract-worker` | Master 向 Worker 派发、暂停、终止、接管物理任务 |
| `ITaskExecutorQueryClient` | `dolphinscheduler-extract-worker` | 查询 Worker 上任务执行状态 |
| `IAlertOperator` | `dolphinscheduler-extract-alert` | API/Master 调用 Alert Server 发送告警或测试告警 |
| `ILogService` | `dolphinscheduler-extract-common` | API 远程读取 Worker/Master 日志 |

### 5.2 Netty 使用能力

| 能力 | 源码体现 |
| --- | --- |
| RPC 客户端代理 | `Clients.withService(...).withHost(...).build()` 使用 JDK 动态代理生成远程服务客户端 |
| RPC 服务发现 | `SpringServerMethodInvokerDiscovery` 作为 `BeanPostProcessor` 自动发现 Spring Bean 中的 RPC 方法 |
| Netty Server | `NettyRemotingServer` 绑定监听端口，初始化 Boss/Worker EventLoop |
| Netty Client | `NettyRemotingClient` 管理连接、发送同步请求 |
| 编解码 | `TransporterEncoder`、`TransporterDecoder` 对 `Transporter` 协议编码/解码 |
| 心跳 | `HeartBeatTransporter`、`IdleStateHandler` 维持连接活性 |
| 同步等待 | 客户端发送请求后按 opaque 等待响应，支持超时 |
| 重试 | RPC 方法注解配置 retry strategy，客户端按策略重试 |
| 指标 | `RpcMetrics` 采集同步请求耗时和异常计数 |

### 5.3 典型调用链路

| 场景 | 链路 |
| --- | --- |
| 手动运行工作流 | API Controller -> ExecutorDelegate -> `Clients.withService(IWorkflowControlClient)` -> Master RPC -> 创建 Command |
| 定时触发工作流 | Quartz `ProcessScheduleTask` -> `IWorkflowControlClient.scheduleTriggerWorkflow` -> Master |
| 派发任务 | Master Task Executor -> `IPhysicalTaskExecutorOperator` -> Worker -> 物理任务执行 |
| 发送告警 | Master/API -> `IAlertOperator` -> Alert Server -> Alert 插件 |
| 读取日志 | API -> `ILogService` -> Worker/Master 日志服务 -> 返回日志内容 |

## 7. 资源存储和远程日志中间件

项目通过 `StorageOperator` 和 `StorageOperatorFactory` 抽象资源存储。`StorageConfiguration` 读取 `resource.storage.type`，通过 `ServiceLoader` 选择一个实际存储后端。

### 7.1 支持的资源存储

| 存储类型 | 模块 | 使用能力 |
| --- | --- | --- |
| LOCAL | `dolphinscheduler-storage-api` | 本地文件存储；默认类型；适合单机或共享挂载目录 |
| HDFS | `dolphinscheduler-storage-hdfs` | HDFS 文件/目录管理、上传下载、Kerberos 认证支持 |
| S3 | `dolphinscheduler-storage-s3` | S3/S3A 对象存储；Helm 默认用 MinIO 演示 |

## 12. 告警插件使用的中间件

### 12.1 告警发送链路

AlertPluginManager 获取 AlertChannel
具体告警插件发送消息

## 16. 最终结论

这个项目的核心中间件组合可以概括为：

| 层次 | 中间件 |
| --- | --- |
| 元数据层 | PostgreSQL/MySQL/H2 + HikariCP + MyBatis Plus |
| 调度层 | Quartz JDBC JobStore |
| 注册与 HA 层 | ZooKeeper 默认，Etcd/JDBC Registry 可选 |
| 通信层 | Netty RPC |
| Web/API 层 | Spring Boot + Spring MVC + Jetty |
| 监控层 | Actuator + Micrometer + Prometheus |
| 安全层 | Spring Security + Password/LDAP/OAuth2/OIDC/Casdoor |
| 存储层 | LOCAL/HDFS/S3/OSS/GCS/ABS/OBS/COS |
| 任务生态 | Hadoop/YARN/Spark/Flink/Hive/Kubernetes/DataX/Sqoop/云服务/Notebook/MLOps 等插件型外部系统 |
| 告警生态 | Email、IM Webhook、HTTP、Script、PagerDuty、Alertmanager、阿里云语音等插件型通道 |

从源码看，DolphinScheduler 刻意减少内部强依赖：没有把 Redis、Kafka、RabbitMQ、RocketMQ、Elasticsearch、Nacos、Consul、Eureka 作为核心中间件；内部调度命令主要依赖数据库表，服务发现和高可用依赖 Registry，进程间调用依赖 Netty RPC，扩展能力则通过 SPI 插件接入外部中间件。
