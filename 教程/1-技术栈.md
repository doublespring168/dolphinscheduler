# DolphinScheduler 技术栈

本文档根据当前项目的 `pom.xml`、`dolphinscheduler-bom/pom.xml`、`dolphinscheduler-ui/package.json`、`vite.config.ts` 和主要源码入口整理，说明前端、后端分别使用了哪些核心技术栈，以及这些技术栈在项目中的主要功能。

## 1. 总览

| 端 | 核心技术 | 主要作用 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Naive UI、Pinia、Vue Router、Axios、AntV X6、ECharts、D3、Monaco Editor | 构建 DolphinScheduler Web 控制台，提供工作流 DAG 编辑、项目管理、资源管理、数据源、安全、监控等页面 |
| 后端 | Java 8、Maven、Spring Boot、Spring MVC、MyBatis Plus、HikariCP、Quartz、Netty、ServiceLoader SPI、ZooKeeper/JDBC/Etcd Registry、Micrometer、Hadoop/K8s/云 SDK | 构建 API、Master、Worker、Alert 等服务，实现分布式调度、任务执行、插件扩展、资源管理、监控告警和部署交付 |

## 4. 前后端协作方式

```text
Vue 页面
  -> service/modules API 封装
  -> Axios 请求 /dolphinscheduler/*
  -> Spring MVC Controller
  -> API Service 做鉴权和参数校验
  -> DAO/Service 访问元数据
  -> Registry 选择 Master
  -> Extract RPC 调用 Master/Worker/Alert
  -> Master 调度工作流
  -> Worker 执行任务插件
  -> Alert 发送告警
```

主要协作点：

| 协作点 | 说明 |
| --- | --- |
| REST API | 前端只直接访问 API Server，不直接访问 Master/Worker/Alert |
| Session | 登录后前端保存 `sessionId`，后续请求通过请求头传给 API |
| 路由与权限 | 前端展示项目、资源、安全等页面；后端 API 做真正的权限校验 |
| DAG 编辑 | 前端用 X6 编辑 DAG，后端保存工作流定义、任务定义和任务关系 |
| 任务类型 | 后端任务插件注册后，API 可提供任务类型/参数信息，前端根据任务类型展示对应表单 |
| 调度执行 | 前端发起启动/停止/补数等操作，API 通过 Registry + RPC 调用 Master |
| 日志查看 | 前端请求 API 日志接口，API 根据任务所在节点读取本地或远程日志 |

## 6. 阅读技术栈的建议顺序

1. 先看 `dolphinscheduler-ui/package.json` 和 `src/service/service.ts`，理解前端如何请求 API。
2. 再看 `dolphinscheduler-api/src/main/java/.../ApiApplicationServer.java` 和 `controller` 包，理解后端 HTTP 入口。
3. 继续看 `dolphinscheduler-master` 的 `MasterServer`、`CommandEngine`、`WorkflowEngine`，理解调度主链路。
4. 看 `dolphinscheduler-worker` 的 `WorkerServer`、`PhysicalTaskExecutor`，理解任务如何真正执行。
5. 看 `dolphinscheduler-extract` 和 `dolphinscheduler-registry`，理解服务间通信和服务发现。
6. 看 `task/datasource/storage/alert` 插件 API，理解项目可扩展点。
