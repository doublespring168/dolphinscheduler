# 17-手动启动步骤

本文整理当前项目在 **MySQL 元数据库、多机部署、手动 `docker run` 启动、不使用 Docker volume、不使用自定义 Docker bridge 网络** 时的启动步骤。

本文命令默认运行在 Linux 服务器上。多机部署建议使用 `--network host`，让 Master、Worker、Alert、API 注册到 ZooKeeper 的地址是宿主机真实地址，而不是 Docker bridge 容器内网地址。

## 0、加载镜像

```

# 导入新镜像

for line in `ls ./`; do 
  echo ""; 
  echo "--->导入镜像【 $line 】"; 
  docker load -i $line; 
done



```

## 1. 部署目标

核心服务如下：

| 服务             | 作用                                                          | 镜像                                     |
| ---------------- | ------------------------------------------------------------- | ---------------------------------------- |
| MySQL            | 元数据库，保存业务表、Quartz 表、命令、实例、资源、告警等数据 | 通常使用已有 MySQL，不在本文主命令中启动 |
| ZooKeeper        | 注册中心，保存 Master/Worker/Alert 心跳和服务发现信息         | 可使用已有 ZooKeeper，也可按本文命令启动 |
| `gyyun-tools`  | 初始化/升级 MySQL Schema                                      | `${HUB}/gyyun-tools:${TAG}`            |
| `gyyun-alert`  | Alert Server                                                  | `${HUB}/gyyun-alert-server:${TAG}`     |
| `gyyun-worker` | Worker Server                                                 | `${HUB}/gyyun-worker:${TAG}`           |
| `gyyun-master` | Master Server                                                 | `${HUB}/gyyun-master:${TAG}`           |
| `gyyun-api`    | API Server 和 UI 入口                                         | `${HUB}/gyyun-api:${TAG}`              |

业务镜像的默认启动入口来自 `gyyun-dist/src/main/docker/*.dockerfile`：

| 镜像                                 | 默认入口                                                               |
| ------------------------------------ | ---------------------------------------------------------------------- |
| `${HUB}/gyyun-api:${TAG}`          | `/bin/bash /gyy_program/api-server/bin/start.sh`                     |
| `${HUB}/gyyun-master:${TAG}`       | `/bin/bash /gyy_program/master-server/bin/start.sh`                  |
| `${HUB}/gyyun-worker:${TAG}`       | `/bin/bash /gyy_program/worker-server/bin/start.sh`                  |
| `${HUB}/gyyun-alert-server:${TAG}` | `/bin/bash /gyy_program/alert-server/bin/start.sh`                   |
| `${HUB}/gyyun-tools:${TAG}`        | `ENTRYPOINT ["/bin/bash"]`，手动追加 `tools/bin/upgrade-schema.sh` |

当前 Dockerfile 已把运行目录改为 `/gyy_program`，并创建运行用户：

```text
用户：gyy
UID：2025
组：gyy
GID：2025
```

因此宿主机 bind mount 的目录必须允许 UID/GID `2025:2025` 写入。

## 2. 多机规划

下面是一种推荐规划，实际可以合并或拆分：

| 机器           | 示例 IP                      | 运行服务                 |
| -------------- | ---------------------------- | ------------------------ |
| MySQL 机器     | `10.0.0.10`                | MySQL                    |
| ZooKeeper 机器 | `10.0.0.11`                | ZooKeeper                |
| Alert 机器     | `10.0.0.21`                | `gyyun-alert`          |
| Worker 机器    | `10.0.0.22`、`10.0.0.23` | `gyyun-worker`，可多台 |
| Master 机器    | `10.0.0.31`、`10.0.0.32` | `gyyun-master`，可多台 |
| API 机器       | `10.0.0.41`                | `gyyun-api`            |

多机部署的关键点：

| 项              | 要求                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 网络模式        | 业务容器使用 `--network host`                                                                                         |
| MySQL 地址      | 所有服务都使用 MySQL 机器真实 IP/域名                                                                                   |
| ZooKeeper 地址  | 所有服务都使用 ZooKeeper 机器真实 IP/域名                                                                               |
| 服务端口        | 各机器防火墙需要放通对应端口                                                                                            |
| 资源目录        | 如果 `RESOURCE_STORAGE_TYPE=LOCAL`，`/gyyun` 必须是所有 API/Worker 能看到的共享目录，例如 NFS；否则建议改用 S3/HDFS |
| 日志目录        | 每台机器可以使用本地目录，各服务写自己的日志                                                                            |
| Worker 数据目录 | 每台 Worker 使用自己的本地目录                                                                                          |

需要放通的端口：

| 服务      | 端口                    | 说明                             |
| --------- | ----------------------- | -------------------------------- |
| MySQL     | `3306` 或你的实际端口 | 元数据库                         |
| ZooKeeper | `2181`                | 注册中心                         |
| Alert     | `50052`               | Alert RPC                        |
| Alert     | `50053`               | Alert Actuator                   |
| Worker    | `1234`                | Worker RPC                       |
| Worker    | `1235`                | Worker Actuator                  |
| Master    | `5678`                | Master RPC                       |
| Master    | `5679`                | Master Actuator                  |
| API       | `12345`               | API/UI                           |
| API       | `25333`               | Python Gateway，未启用时可不开放 |

## 3. 启动顺序

推荐顺序：

```text
1. 准备 MySQL 数据库和账号
2. 准备 ZooKeeper
3. 在每台业务机器创建宿主机目录并设置 UID/GID 2025 权限
4. 执行 gyyun-tools 初始化/升级 MySQL Schema，只执行一次
5. 启动 Alert Server
6. 启动 Worker Server
7. 启动 Master Server
8. 启动 API Server
9. 检查健康状态并访问 UI
```

原因：

| 顺序点                 | 原因                                            |
| ---------------------- | ----------------------------------------------- |
| MySQL 先准备           | Tools、API、Master、Alert 都依赖元数据库        |
| ZooKeeper 先准备       | Master、Worker、Alert、API 都需要注册中心       |
| Tools 在业务服务前执行 | 业务服务不会自动建表或升级表                    |
| Alert 早于业务执行链路 | 工作流失败或告警测试时已有 Alert 可用           |
| Worker 早于 Master     | Master 启动后能尽早看到可用 Worker              |
| API 最后               | 避免用户过早触发工作流但 Master/Worker 尚未就绪 |

## 4. 通用变量

在每台要执行命令的机器上设置。请把 IP、端口、账号、密码替换成你的真实值。

```bash

export HUB='r.gyykj.com/gyy-base'
export TAG='3.4.3-SNAPSHOT'
export GYY_HOME=/gyy_program
export GYY_HOST_LOGS="/gyy_logs/logs"
export GYY_HOST_SOFT="/gyy_program/soft"
export GYY_HOST_RESOURCE="/gyy_program/resource"
export GYY_HOST_WORKER_DATA="/gyy_workspace/worker-data"
export GYY_DATABASE=mysql
export GYY_MYSQL_HOST=192.168.122.6
export GYY_MYSQL_PORT=3317
export GYY_MYSQL_DATABASE=ala-data-ds
export GYY_MYSQL_USER=gyy
export GYY_MYSQL_PASSWORD=gyyun
export GYY_MYSQL_URL="jdbc:mysql://${GYY_MYSQL_HOST}:${GYY_MYSQL_PORT}/${GYY_MYSQL_DATABASE}?useUnicode=true&characterEncoding=UTF-8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai"
export GYY_ZK_CONNECT=192.168.122.6:4206

# 多网卡机器建议设置为真实业务网卡名，例如 eth0、ens192、bond0。
export GYY_NIC=eth0

```

参数说明：

| 参数                      | 说明                                             |
| ------------------------- | ------------------------------------------------ |
| `HUB`                   | 业务镜像仓库                                     |
| `TAG`                   | 业务镜像标签                                     |
| `GYY_HOME=/gyy_program` | 当前 Dockerfile 中的程序安装目录                 |
| `GYY_HOST_BASE`         | 宿主机目录根路径，不使用 Docker volume           |
| `GYY_HOST_LOGS`         | 宿主机日志目录                                   |
| `GYY_HOST_SOFT`         | 宿主机共享软件/依赖目录，映射到 `/opt/soft`    |
| `GYY_HOST_RESOURCE`     | 宿主机资源目录，映射到 `/gyyun`                |
| `GYY_HOST_WORKER_DATA`  | Worker 宿主机任务数据目录，映射到 `/tmp/gyyun` |
| `GYY_HOST_ZK_DATA`      | ZooKeeper 宿主机数据目录                         |
| `GYY_MYSQL_URL`         | 所有 Java 服务使用的 MySQL JDBC URL              |
| `GYY_ZK_CONNECT`        | 所有 Java 服务使用的 ZooKeeper 连接串            |
| `GYY_NIC`               | 多网卡时指定注册到 ZooKeeper 的宿主机业务网卡    |

如果你的 MySQL 端口沿用当前项目配置示例中的 `3317`，把 `GYY_MYSQL_PORT` 改为 `3317` 即可。

## 7. 准备业务宿主机目录

在每台会运行 `gyyun-tools`、`gyyun-alert`、`gyyun-worker`、`gyyun-master`、`gyyun-api` 的机器上执行。

```bash
sudo mkdir -p \
  "${GYY_HOST_LOGS}" \
  "${GYY_HOST_SOFT}" \
  "${GYY_HOST_RESOURCE}" \
  "${GYY_HOST_WORKER_DATA}"

sudo chown -R 2025:2025 \
  "${GYY_HOST_LOGS}" \
  "${GYY_HOST_SOFT}" \
  "${GYY_HOST_RESOURCE}" \
  "${GYY_HOST_WORKER_DATA}"
```

目录说明：

| 宿主机目录                  | 容器目录              | 使用服务                      | 说明                     |
| --------------------------- | --------------------- | ----------------------------- | ------------------------ |
| `${GYY_HOST_LOGS}`        | `/gyy_program/logs` | API/Master/Worker/Alert/Tools | 服务日志                 |
| `${GYY_HOST_SOFT}`        | `/opt/soft`         | API/Master/Worker/Tools       | 共享软件、任务依赖、驱动 |
| `${GYY_HOST_RESOURCE}`    | `/gyyun`            | API/Worker/Tools              | 本地资源中心目录         |
| `${GYY_HOST_WORKER_DATA}` | `/tmp/gyyun`        | Worker                        | Worker 任务执行数据      |

多机部署如果继续使用 `RESOURCE_STORAGE_TYPE=LOCAL`，`${GYY_HOST_RESOURCE}` 不能只是每台机器各自的本地目录。它需要是所有相关机器挂载到同一路径的共享存储，例如 NFS。否则 API 上传的资源文件可能 Worker 机器看不到。

## 8. 初始化 MySQL Schema

只执行一次。建议在能访问 MySQL 的任意一台业务机器上执行。

```bash

# 运行
docker rm -f gyyun-schema-initializer 2>/dev/null || true

docker run --rm \
  --name gyyun-schema-initializer \
  --network host \
  -e TZ=Asia/Shanghai \
  -e DATABASE=mysql \
  -e SPRING_DATASOURCE_URL="${GYY_MYSQL_URL}" \
  -e SPRING_DATASOURCE_USERNAME="${GYY_MYSQL_USER}" \
  -e SPRING_DATASOURCE_PASSWORD="${GYY_MYSQL_PASSWORD}" \
  -e SPRING_JACKSON_TIME_ZONE=UTC \
  -e DOLPHINSCHEDULER_HOME="${GYY_HOME}" \
  -e SUDO_ENABLE=false \
  -v "${GYY_HOST_LOGS}:${GYY_HOME}/logs" \
  -v "${GYY_HOST_SOFT}:/opt/soft" \
  -v "${GYY_HOST_RESOURCE}:/gyyun" \
  "${HUB}/ala-ds-tools:${TAG}" \
  tools/bin/upgrade-schema.sh

```

参数说明：

| 参数                                    | 说明                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------- |
| `--network host`                      | 直接访问宿主机网络中的 MySQL                                            |
| `DATABASE=mysql`                      | `upgrade-schema.sh` 会拼成 `-Dspring.profiles.active=upgrade,mysql` |
| `SPRING_DATASOURCE_URL`               | MySQL JDBC URL                                                          |
| `SPRING_DATASOURCE_USERNAME/PASSWORD` | MySQL 账号和密码                                                        |
| `SUDO_ENABLE=false`                   | 当前业务镜像运行用户是 `gyy`，初始化阶段不需要 sudo 租户切换          |
| `tools/bin/upgrade-schema.sh`         | 初始化或升级业务表、Quartz 表                                           |

注意：Schema 初始化不要多个容器并发执行，同一个库只跑一次。

## 9. 启动 Alert Server

在 Alert 机器执行：

```bash

# 运行
docker rm -f gyyun-alert 2>/dev/null || true

docker run -d \
  --name gyyun-alert \
  --network host \
  --restart unless-stopped \
  -e TZ=Asia/Shanghai \
  -e DATABASE=mysql \
  -e SPRING_PROFILES_ACTIVE=mysql \
  -e SPRING_DATASOURCE_URL="${GYY_MYSQL_URL}" \
  -e SPRING_DATASOURCE_USERNAME="${GYY_MYSQL_USER}" \
  -e SPRING_DATASOURCE_PASSWORD="${GYY_MYSQL_PASSWORD}" \
  -e SPRING_JACKSON_TIME_ZONE=UTC \
  -e REGISTRY_ZOOKEEPER_CONNECT_STRING="${GYY_ZK_CONNECT}" \
  -e DOLPHINSCHEDULER_HOME="${GYY_HOME}" \
  -e SUDO_ENABLE=false \
  -e DOLPHIN_SCHEDULER_NETWORK_INTERFACE_PREFERRED="${GYY_NIC}" \
  -v "${GYY_HOST_LOGS}:${GYY_HOME}/logs" \
  --health-cmd='wget -q -O - http://127.0.0.1:50053/actuator/health >/dev/null 2>&1 || exit 1' \
  --health-interval=30s \
  --health-timeout=5s \
  --health-retries=3 \
  "${HUB}/ala-ds-alert-server:${TAG}"

```

参数说明：

| 参数                                              | 说明                                                     |
| ------------------------------------------------- | -------------------------------------------------------- |
| `--network host`                                | Alert RPC `50052` 和 Actuator `50053` 直接监听宿主机 |
| `SPRING_PROFILES_ACTIVE=mysql`                  | 明确启用 MySQL profile                                   |
| `REGISTRY_ZOOKEEPER_CONNECT_STRING`             | 连接多机共享 ZooKeeper                                   |
| `DOLPHIN_SCHEDULER_NETWORK_INTERFACE_PREFERRED` | 多网卡时指定注册到 ZooKeeper 的业务网卡                  |
| `SUDO_ENABLE=false`                             | 避免非 root 运行用户缺少 sudoers 权限                    |

健康检查：

```bash

# 运行
curl http://127.0.0.1:50053/actuator/health

```

## 10. 启动 Worker Server

在每台 Worker 机器执行。多台 Worker 可以使用相同命令，各自有本机 `${GYY_HOST_WORKER_DATA}`。

```bash

# 运行
docker rm -f gyyun-worker 2>/dev/null || true

docker run -d \
  --name gyyun-worker \
  --network host \
  --restart unless-stopped \
  -e TZ=Asia/Shanghai \
  -e DATABASE=mysql \
  -e SPRING_JACKSON_TIME_ZONE=UTC \
  -e REGISTRY_ZOOKEEPER_CONNECT_STRING="${GYY_ZK_CONNECT}" \
  -e DOLPHINSCHEDULER_HOME="${GYY_HOME}" \
  -e SUDO_ENABLE=false \
  -e DATA_BASEDIR_PATH=/tmp/gyyun \
  -e RESOURCE_STORAGE_TYPE=LOCAL \
  -e RESOURCE_STORAGE_UPLOAD_BASE_PATH=/gyyun \
  -e WORKER_TENANT_CONFIG_AUTO_CREATE_TENANT_ENABLED=true \
  -e WORKER_TENANT_CONFIG_DEFAULT_TENANT_ENABLED=true \
  -e DOLPHIN_SCHEDULER_NETWORK_INTERFACE_PREFERRED="${GYY_NIC}" \
  -v "${GYY_HOST_WORKER_DATA}:/tmp/gyyun" \
  -v "${GYY_HOST_LOGS}:${GYY_HOME}/logs" \
  -v "${GYY_HOST_SOFT}:/opt/soft" \
  -v "${GYY_HOST_RESOURCE}:/gyyun" \
  --health-cmd='wget -q -O - http://127.0.0.1:1235/actuator/health >/dev/null 2>&1 || exit 1' \
  --health-interval=30s \
  --health-timeout=5s \
  --health-retries=3 \
  "${HUB}/ala-ds-worker:${TAG}"


```

参数说明：

| 参数                                                 | 说明                                                    |
| ---------------------------------------------------- | ------------------------------------------------------- |
| `--network host`                                   | Worker RPC `1234` 和 Actuator `1235` 直接监听宿主机 |
| `REGISTRY_ZOOKEEPER_CONNECT_STRING`                | Worker 注册到 ZooKeeper，供 Master 发现                 |
| `DATA_BASEDIR_PATH=/tmp/gyyun`                     | Worker 任务执行数据目录                                 |
| `RESOURCE_STORAGE_UPLOAD_BASE_PATH=/gyyun`         | 本地资源中心目录                                        |
| `WORKER_TENANT_CONFIG_DEFAULT_TENANT_ENABLED=true` | 默认租户任务使用启动用户                                |
| `SUDO_ENABLE=false`                                | 任务使用容器用户 `gyy` 执行                           |

健康检查：

```bash
curl http://127.0.0.1:1235/actuator/health
```

```bash
  --health-cmd='wget -q -O - http://127.0.0.1:12345/gyyun/actuator/health >/dev/null 2>&1 || exit 1' \
  --health-interval=30s \
  --health-timeout=5s \
  --health-retries=3 \
  "${HUB}/ala-ds-api:${TAG}"


```

## 15. 参数总表

| 参数                                                 | 用于                                    | 说明                                               |
| ---------------------------------------------------- | --------------------------------------- | -------------------------------------------------- |
| `--network host`                                   | ZooKeeper/Tools/API/Master/Worker/Alert | 多机部署推荐方式，避免注册容器 bridge IP           |
| `DATABASE=mysql`                                   | Tools/API/Master/Worker/Alert           | 数据库类型；Tools 脚本会用它拼接 profile           |
| `SPRING_PROFILES_ACTIVE=mysql`                     | API/Master/Alert                        | 明确启用 MySQL profile                             |
| `SPRING_DATASOURCE_URL`                            | Tools/API/Master/Alert                  | MySQL JDBC URL                                     |
| `SPRING_DATASOURCE_USERNAME`                       | Tools/API/Master/Alert                  | MySQL 用户名                                       |
| `SPRING_DATASOURCE_PASSWORD`                       | Tools/API/Master/Alert                  | MySQL 密码                                         |
| `SPRING_JACKSON_TIME_ZONE=UTC`                     | Tools/API/Master/Worker/Alert           | JSON 时间序列化时区，沿用项目 Docker 配置          |
| `REGISTRY_ZOOKEEPER_CONNECT_STRING`                | API/Master/Worker/Alert                 | ZooKeeper 注册中心地址，使用真实 IP/域名           |
| `DOLPHINSCHEDULER_HOME=/gyy_program`               | 所有业务镜像                            | 当前 Dockerfile 中的安装目录                       |
| `SUDO_ENABLE=false`                                | 尤其是 Worker                           | 当前容器运行用户是 `gyy`，关闭 sudo 租户切换更稳 |
| `DOLPHIN_SCHEDULER_NETWORK_INTERFACE_PREFERRED`    | API/Master/Worker/Alert                 | 多网卡时指定注册到 ZooKeeper 的业务网卡            |
| `DATA_BASEDIR_PATH=/tmp/gyyun`                     | Worker                                  | 任务执行临时数据目录                               |
| `RESOURCE_STORAGE_TYPE=LOCAL`                      | API/Master/Worker                       | 使用本地资源中心                                   |
| `RESOURCE_STORAGE_UPLOAD_BASE_PATH=/gyyun`         | API/Master/Worker                       | 本地资源中心根目录                                 |
| `WORKER_TENANT_CONFIG_DEFAULT_TENANT_ENABLED=true` | Worker                                  | 默认租户任务使用 Worker 启动用户                   |
| `-v 宿主机目录:容器目录`                           | 所有容器                                | 使用宿主机 bind mount，不使用 Docker volume        |

## 16. 常见问题

| 现象                                 | 排查点                                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| API/Master/Alert 仍加载非 MySQL 配置 | 确认设置了 `DATABASE=mysql` 和 `SPRING_PROFILES_ACTIVE=mysql`                                            |
| 连接 MySQL 失败                      | 确认 `GYY_MYSQL_URL`、账号、密码、授权来源、防火墙和 MySQL bind 地址                                       |
| 业务服务连接不到 ZooKeeper           | 确认 `GYY_ZK_CONNECT` 是真实 IP/域名，且各机器能访问 `2181`                                              |
| Master 看不到 Worker                 | 确认 Worker 使用 `--network host`，并且 `DOLPHIN_SCHEDULER_NETWORK_INTERFACE_PREFERRED` 指向真实业务网卡 |
| Worker 执行任务时报 sudo 权限问题    | 确认 `SUDO_ENABLE=false`；若必须开启租户 sudo，需要额外配置 `gyy` 的 sudoers 权限                        |
| 资源文件 API 上传后 Worker 找不到    | 多机 `LOCAL` 资源目录必须是共享存储；或改用 S3/HDFS                                                        |
| 容器提示日志或资源目录无权限         | 确认宿主机目录已 `chown -R 2025:2025`                                                                      |
| healthcheck 一直失败但进程正常       | 当前 Alpine 镜像若没有 `wget`，需要在 Dockerfile 安装 `curl`，或把 healthcheck 改成镜像中存在的命令      |
| `--network host` 下 `-p` 不生效  | host 网络直接使用宿主机端口，不需要也不能依赖 `-p`                                                         |
