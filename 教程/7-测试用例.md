## 二、测试类型

| 类型 | 位置 | 框架/方式 | 测试目标 |
| --- | --- | --- | --- |
| 单元测试 | 各模块 `src/test/java` | JUnit 5、Mockito、AssertJ | 验证工具类、服务方法、插件参数、DAO、调度逻辑 |
| Controller 测试 | `dolphinscheduler-api/src/test/java/.../controller` | Mockito、Spring Boot Test、MockMvc | 验证 API Controller 方法、请求参数、响应结构、Service 调用 |
| API 集成测试 | `dolphinscheduler-api-test` | Testcontainers、Docker Compose、HTTP Page Object | 启动 DolphinScheduler 测试栈后调用真实 HTTP API |

| 数据库 IT | `dolphinscheduler-tools/src/test/java` | Testcontainers、MySQL/PostgreSQL | 验证数据库 schema 初始化和升级 |
| 插件测试 | `dolphinscheduler-task-plugin`、`dolphinscheduler-datasource-plugin`、`dolphinscheduler-alert`、`dolphinscheduler-storage-plugin` | JUnit 5、Mockito、WireMock/资源文件 | 验证插件参数解析、命令构造、状态映射、外部服务交互 |

## 十、接口覆盖度

### 统计口径

接口覆盖度不是 JaCoCo 运行报告，而是源码静态估算：

1. 从 `dolphinscheduler-api/src/main/java/org/apache/dolphinscheduler/api/controller` 解析 `@GetMapping`、`@PostMapping`、`@PutMapping`、`@DeleteMapping`、`@RequestMapping`。
2. 统计得到 243 个业务 Controller 接口。
3. Controller 单元测试覆盖：匹配 ControllerTest 中的 Controller 方法调用或 MockMvc URL。
4. API 集成测试覆盖：匹配 `dolphinscheduler-api-test` 中实际被 `APITest` 调用的 Page Object HTTP URL。
5. Actuator、OpenAPI、Swagger UI、前端静态资源端点不计入该覆盖率。
6. E2E 测试会通过浏览器间接调用 API，但本节不把浏览器行为反推为具体 API URL 覆盖。

## 十一、结论

当前项目测试重点放在后端单元测试、插件能力、DAO/Mapper、API 集成和 UI E2E 上。核心业务如项目、租户、WorkerGroup、工作流定义/实例、调度、登录认证、任务插件、数据源插件覆盖较充分；相对薄弱的是 Cloud、动态任务类型、收藏任务、TaskDefinition Controller、ProjectWorkerGroup、部分资源/监控/血缘接口的直接 API 覆盖。

若后续补测试，优先建议补齐未覆盖 Controller 的 MockMvc/API 集成测试，尤其是 `TaskDefinitionController`、`CloudController`、`DynamicTaskTypeController`、`FavTaskController`、`ProjectWorkerGroupController` 和 `WorkflowLineageController`。
