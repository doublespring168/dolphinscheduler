# 数据库升级教程

本文记录当前项目的数据库初始化与升级机制，以及本机开发调试时的执行方式。


## 1. 结论

当前项目没有使用 Flyway、Liquibase 这类数据库迁移框架。

数据库初始化和升级由 `gyyun-tools` 模块中的独立工具负责，入口类是：

```text
com.gyyun.ds.tools.datasource.UpgradeDolphinScheduler
```

发行包中对应脚本是：

```bash
tools/bin/upgrade-schema.sh
```

普通业务服务启动时不会自动同步数据库结构，包括：

```text
ApiApplicationServer
MasterServer
WorkerServer
AlertServer
StandaloneServer
```

因此，在本机使用 MySQL 或 PostgreSQL 启动普通模式前，需要先单独执行数据库初始化或升级。

## 2. 相关模块和文件

| 位置                                                                                     | 作用                                     |
| ---------------------------------------------------------------------------------------- | ---------------------------------------- |
| `gyyun-tools`                                                                          | 数据库初始化和升级工具模块               |
| `gyyun-tools/src/main/java/com/gyyun/ds/tools/datasource/UpgradeDolphinScheduler.java` | 升级工具启动入口                         |
| `gyyun-tools/src/main/java/com/gyyun/ds/tools/datasource/DolphinSchedulerManager.java` | 判断是否初始化、调度初始化或升级         |
| `gyyun-tools/src/main/java/com/gyyun/ds/tools/datasource/upgrader/UpgradeDao.java`     | 执行初始化 SQL、升级 DDL/DML、更新版本号 |
| `gyyun-tools/src/main/java/com/gyyun/ds/tools/datasource/utils/SchemaUtils.java`       | 读取升级目录和当前软件版本               |
| `gyyun-dao/src/main/resources/sql/gyyun_mysql.sql`                                     | MySQL 全量初始化 SQL                     |
| `gyyun-dao/src/main/resources/sql/gyyun_postgresql.sql`                                | PostgreSQL 全量初始化 SQL                |
| `gyyun-dao/src/main/resources/sql/upgrade/*_schema/{mysql,postgresql}`                 | 各版本增量升级 SQL                       |
| `gyyun-dao/src/main/resources/sql/soft_version`                                        | 当前软件版本号                           |

## 3. 初始化和升级逻辑

`UpgradeDolphinScheduler` 启动后，会在 `upgrade` profile 下执行 `CommandLineRunner`。

整体逻辑如下：

```text
启动 UpgradeDolphinScheduler
  -> 判断数据库是否已经初始化
    -> 未初始化：执行全量初始化 SQL
    -> 已初始化：执行增量升级 SQL
  -> 更新版本表
```

判断数据库是否已初始化时，会检查以下表是否存在：

```text
t_escheduler_version
t_ds_version
t_escheduler_queue
```

如果这些表都不存在，则认为数据库未初始化，执行：

```text
sql/gyyun_mysql.sql
```

或：

```text
sql/gyyun_postgresql.sql
```

具体使用哪个 SQL 取决于当前数据库类型。

如果数据库已初始化，则读取当前版本表：

```text
t_ds_version
```

然后按版本顺序扫描：

```text
sql/upgrade/*_schema
```

对高于当前数据库版本的目录依次执行：

```text
gyyun_ddl.sql
gyyun_dml.sql
```

最后将版本更新为 `sql/soft_version` 中记录的软件版本。

## 4. 本机 IDEA 执行方式

在 IDEA 中新增一个 Run Configuration：

```text
Name: gyyun-upgrade-schema
Main class: com.gyyun.ds.tools.datasource.UpgradeDolphinScheduler
Module classpath: gyyun-tools
Working directory: 项目根目录
```

MySQL 示例 VM options：

```text
-Dspring.profiles.active=upgrade,mysql
-Dspring.datasource.url=jdbc:mysql://127.0.0.1:3306/gyyun?useUnicode=true&characterEncoding=UTF-8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
-Dspring.datasource.username=root
-Dspring.datasource.password=root
```

PostgreSQL 示例 VM options：

```text
-Dspring.profiles.active=upgrade,postgresql
-Dspring.datasource.url=jdbc:postgresql://127.0.0.1:5432/gyyun
-Dspring.datasource.username=root
-Dspring.datasource.password=root
```

运行成功后，再启动业务服务：

```text
AlertServer
MasterServer
WorkerServer
ApiApplicationServer
```

## 5. 命令行执行方式

如果已经构建出发行包，可以使用脚本：

```bash
tools/bin/upgrade-schema.sh
```

脚本内部会以如下 profile 启动工具类：

```text
upgrade,${DATABASE}
```

MySQL 示例环境变量：

```bash
export DATABASE=mysql
export SPRING_DATASOURCE_URL="jdbc:mysql://127.0.0.1:3306/gyyun?useUnicode=true&characterEncoding=UTF-8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai"
export SPRING_DATASOURCE_USERNAME=root
export SPRING_DATASOURCE_PASSWORD=root
```

然后执行：

```bash
bash tools/bin/upgrade-schema.sh
```

## 6. Docker 和 Kubernetes 中的策略

容器部署也不是由 API、Master、Worker、Alert 自动升级数据库。

Docker Compose 中有独立的 schema 初始化服务：

```text
gyyun-schema-initializer
```

其命令是：

```text
tools/bin/upgrade-schema.sh
```

Kubernetes 部署中也通过独立 Job 执行数据库初始化或升级。

因此部署顺序应是：

```text
数据库启动
  -> 执行 schema 初始化/升级
  -> 启动 ZooKeeper
  -> 启动 Alert/Master/Worker/API
```

## 7. 注意事项

1. 业务服务启动不会自动建表或升级表。
2. `spring.quartz.jdbc.initialize-schema` 配置为 `never`，Quartz 表也依赖初始化 SQL 创建。
3. 初始化和升级应在业务服务启动前执行。
4. 多实例部署时只执行一次升级工具，不要让多个实例同时升级同一个库。
5. 如果手动导入了 `gyyun_mysql.sql` 或 `gyyun_postgresql.sql`，后续版本变更仍应使用 `gyyun-tools` 的升级工具处理增量 SQL。
6. 如果数据库已经存在历史版本，但缺少 `t_ds_version`，升级工具无法判断当前版本，会直接失败，需要先人工确认版本状态。
